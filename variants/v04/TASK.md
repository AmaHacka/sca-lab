# Вариант 04. «Прокси погоды»

Сервис проксирует запросы к внешнему API погоды и кэширует ответы. В образе остался старый Java-модуль кэширования. Go-часть извлекает поля из ответов и логирует запросы.

Вы — инженер по безопасности. Перед выводом сервиса в продуктивную среду нужно провести анализ
состава ПО, оценить найденные уязвимости и довести образы до прохождения security gate.
Общий порядок работы описан в [README.md](../../README.md), здесь — только особенности варианта.

## Состав

| Компонент | Каталог | Образ |
|---|---|---|
| Python-сервис | `python-app/` | `lab4/v04-py:before` |
| Go-сервис | `go-app/` | `lab4/v04-go:before` |

## Сборка исходных образов

```bash
cp -r variants/v04 ~/lab4-<фамилия>-v04 && cd ~/lab4-<фамилия>-v04
mkdir -p sbom scans
docker build -t lab4/v04-py:before python-app
docker build -t lab4/v04-go:before go-app
```

## Индивидуальные вопросы

2. Какие версии Spring нашёл syft в образе? Найдите уязвимость из каталога KEV и объясните, при каких условиях она эксплуатируема. Почему для устранения недостаточно обновиться в пределах ветки 5.3?
