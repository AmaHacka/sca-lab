# Вариант 11. «Агрегатор RSS»

Агрегатор RSS-лент: загружает ленты, очищает HTML, рендерит описания из Markdown. Go-часть на очень старом базовом образе извлекает заголовки страниц.

Вы — инженер по безопасности. Перед выводом сервиса в продуктивную среду нужно провести анализ
состава ПО, оценить найденные уязвимости и довести образы до прохождения security gate.
Общий порядок работы описан в [README.md](../../README.md), здесь — только особенности варианта.

## Состав

| Компонент | Каталог | Образ |
|---|---|---|
| Python-сервис | `python-app/` | `lab4/v11-py:before` |
| Go-сервис | `go-app/` | `lab4/v11-go:before` |

## Сборка исходных образов

```bash
cp -r variants/v11 ~/lab4-<фамилия>-v11 && cd ~/lab4-<фамилия>-v11
mkdir -p sbom scans
docker build -t lab4/v11-py:before python-app
docker build -t lab4/v11-go:before go-app
```

## Что нужно сделать

Подробные инструкции и примеры команд — в разделе 2 [методички](../../README.md#2-порядок-выполнения).

## Индивидуальные вопросы

Ответы оформите в разделе 6 отчёта. Каждое утверждение подтверждайте командой и её выводом (фрагментом).

1. В каталоге `python-app/vendor/` лежит сторонний модуль, скопированный в проект. Нашёл ли его syft? Определите версию модуля по его исходному коду и проверьте её уязвимости (`grype purl`). Как бы вы организовали учёт таких «вендоренных» компонентов?
2. Go-сервис работает на `debian:stretch-slim`. Сколько лет этому дистрибутиву без поддержки? Сравните количество уязвимостей ОС и количество уязвимостей самого приложения.
3. Найдите в отчёте пакет, у которого одна и та же CVE встречается под разными идентификаторами (GHSA, CVE, GO-…). Как работает флаг `--by-cve` и зачем он нужен при подсчёте?
